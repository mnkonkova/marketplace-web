# Сквозные браузерные тесты

Гоняют настоящий браузер по настоящему стеку. Ловят то, чего не видят ни
юнит-тесты, ни сквозные тесты API: кнопку, которая не отправляет запрос,
тумблер, который не откатывается на ошибке, и суммы, показанные в
копейках вместо рублей.

## Что нужно поднять заранее

```bash
cd ../../marketplace-api && make run      # API на :8080
cd ../marketplace-web/web && npx ng serve  # фронт на :4200
```

Стек тесты не поднимают намеренно: иначе падение стека выглядит как
падение теста, и разбираться приходится в обоих сразу.

Нужен docker-контейнер с postgres — в него уходит `seed/users.sql`.

## Запуск

```bash
npm run e2e
```

## Как устроено

`fixtures/world.ts` (globalSetup) делает две разные вещи и делит их
намеренно:

- **пользователей заводит SQL'ем** — войти иначе нечем: регистрация
  требует подтверждения почты, а письма локально никуда не уходят;
- **всё остальное собирает через API** — проект, состав, тариф, выкладки
  создаются теми же запросами, что шлёт интерфейс. Разложить проект по
  таблицам было бы быстрее и бесполезнее: тест проверял бы вёрстку
  поверх состояния, которого приложение не создаёт.

Результат кладётся в `.state/world.json`, специи читают его оттуда.

Специи, кроме `login.spec.ts`, подставляют сессию в localStorage напрямую
— это быстрее и устойчивее, чем проходить форму двадцать раз. Сам вход
при этом проверяется отдельно, иначе его не проверял бы никто.

## Песочницы

У каждой специи (или describe-блока) СВОЙ проект, а где нужно — и свои
люди: `fixtures/sandbox.ts`, `createSandbox()` / `dropSandbox()`.

```ts
let box: Sandbox;
test.beforeAll(async () => {
  box = await createSandbox('метка', { shape: 'history' });
});
test.afterAll(() => dropSandbox(box));
```

Формы проекта: `empty` — состав и тариф без выкладок; `stats` (по
умолчанию) — один сданный ролик с цифрами; `history` — одиннадцать
роликов, первый период подытожен, второй идёт.

Свои люди (`ownCreator`, `ownClient`, `creators: 3`) нужны там, где
специя трогает состояние ЧЕЛОВЕКА, а не проекта. Пример, ради которого
это и заводилось: обход кнопок жал в кабинете креатора тумблер «занят».
Занятость — отметка в `creator_availability`, которую ставит сам
креатор; из выкладок она не выводится. На общем креаторе она оставалась
после прогона, и `order-roster` падала с `creator_busy` — через два
файла и без единой подсказки в отчёте.

Снос — в `afterAll`: он отрабатывает и когда тест упал. Прогон, убитый с
клавиатуры, подчищает `globalSetup` следующего прогона и `globalTeardown`
этого — по метке `(e2e-sandbox)` в названии и префиксу `e2e-sb-` в
адресах.

Тесты идут в один поток. Причина не в проектах — они теперь у каждого
свои, — а в общем стенде: каталог специалистов, список админки и
рейт-лимитер одни на всех.

## Данные

Скрипт трогает только своё — адреса `e2e-*@example.com` и версию условий
с пометкой `E2E`. Перед посевом удаляет следы прошлого прогона, так что
запускать можно сколько угодно раз подряд.
