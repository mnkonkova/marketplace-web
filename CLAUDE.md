# marketplace-web

Фронт маркетплейса: Angular 19, Feature-Sliced Design, standalone-компоненты,
signals, `inject()`, `OnPush`, ng-zorro-antd. Тёмная тема. Код приложения —
в `web/`, в корне — `Caddyfile` и `Dockerfile` прод-образа.

## Структура

`web/src/{pages,widgets,features,entities,shared}` — слои FSD. Алиасы
`@pages/*`, `@widgets/*`, `@features/*`, `@entities/*`, `@shared/*` заданы
в `tsconfig.json`.

Тесты лежат в `web/test-specs/`, а НЕ рядом с кодом. Билдер karma ищет их
по `include` в `angular.json` (`../test-specs/**/*.spec.ts`) — путь
относительно `sourceRoot`, то есть `src`. Сломаешь `include` — karma
найдёт ноль спеков и напишет «Executed 0 of 0 SUCCESS», то есть зелёный
прогон, в котором не выполнилось ничего.

## Перед каждым пушем — прогон тестов локально

GitHub Actions на аккаунте заблокированы по биллингу, CI не проверяет
ничего. Пока это так, гоняем руками:

```bash
cd web
CHROME_BIN=/home/foxxmary/.cache/ms-playwright/chromium-1223/chrome-linux/chrome \
  npm run test:ci
npx ng build --configuration production
npm run e2e:fast        # нужен поднятый стенд, см. ниже
```

Именно `test:ci`, а не `npm test`: в нём лаунчер `ChromeHeadlessNoSandbox`,
без `--no-sandbox` хромиум на этих ядрах не стартует. Системного Chrome
нет, поэтому `CHROME_BIN` обязателен.

Прод-сборка должна проходить без ошибок и без Sass-предупреждений. Если
появились `mixed-decls` — значит в правиле есть декларации после
вложенного правила (частый случай: `@include` с медиа-запросом стоит
перед обычными свойствами; ставь инклуд последним).

### Сквозные тесты обязательны, и вот почему

Юнит-специи РАЗМЕТКУ НЕ ПРОВЕРЯЮТ. В двадцати восьми из семидесяти шести
стоит `TestBed.overrideComponent(..., { set: { template: '' } })` —
шаблон выбрасывается намеренно, проверяется класс. Компонент, у которого
вырезали половину разметки, для них выглядит здоровым, и прод-сборка
молчит тоже: удалить блок — валидный HTML.

Так 22 сентября вместе с переписыванием кабинетов по макетам с карточки
менеджера исчезла вся статистика (просмотры, прирост, график, разбивка
по площадкам), а у креатора из строки ролика — цифры по площадкам.
Сквозные специи это поймали сразу же и были красными двое суток: их
никто не запускал, потому что в этом списке их не было.

**Правило, которое дороже чек-листа: правишь разметку кабинета —
прогоняешь сквозные специи этого кабинета В ТОМ ЖЕ КОММИТЕ.** Не «потом»
и не «перед выкаткой»: через день уже не помнишь, что именно пропало, и
красная специя выглядит сломанной сама по себе.

Набора два:

```bash
npm run e2e:fast   # 112 специй, около четырёх минут — перед каждым пушем
npm run e2e        # все 129 — перед выкаткой и всегда, когда правились кнопки
```

Разница — `buttons-sweep` и `buttons-destructive`: вдвоём они занимают
шестнадцать минут из тридцати (обход каждой кнопки каждой роли и
нажатие всего, что меняет мир). Делит их `E2E_FAST=1` в
`e2e/playwright.config.ts`, файлами, а не пометками в названиях:
название специи здесь — документация.

В полном прогоне обходы идут ПОСЛЕДНИМИ — отдельным проектом
`buttons` с `dependencies: ['chromium']`. Пока они шли по алфавиту в
середине, всё, что после них, начинало отваливаться по времени:
шестнадцать минут непрерывных перезагрузок оставляли dev-сервер
уставшим, `page.goto` не укладывался в тридцать секунд, браузер ронял
сессию. Одиннадцать красных специй, каждая со своей непохожей
ошибкой, — и все сорок из них проходят на спокойном стенде за четыре
минуты.

Сквозные тесты гоняются по УЖЕ ПОДНЯТОМУ стенду и не поднимают его сами
— иначе падение стека выглядит как падение теста:

```bash
cd ../../marketplace-api && make run       # API на :8080
cd ../marketplace-web/web && npx ng serve  # фронт на :4200
```

## Локальный запуск

```bash
cd web && npx ng serve --host 0.0.0.0 --port 4200
```

Фронт ходит в API напрямую по `apiBaseUrl` из `src/environments/`
(dev: `http://192.168.64.2:8080/api/v1`), CORS разрешён в `.env` бэкенда.

## Чего не делать

Не форматировать репозиторий целиком «заодно»: ~110 файлов не по
prettier с прошлых спринтов, и такой коммит утопит ревью. Форматируй
только те файлы, которые правишь.
